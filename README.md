# 技术编辑工作台：选题推荐与机构简称核查

面向技术编辑的单页工作台，包含两个并列功能（顶部标签页切换，互不影响状态）：

1. **阅读推荐**：编辑输入兴趣短文与六个主题的精确篇数配额，系统从 30 篇
   本地文章中选出 6 篇组成阅读队列，在满足**主题精确配额**与**作者不重复**的前提下，
   最大化加权相关度目标，并按每次两篇的节奏逐步揭示。
2. **机构简称核查**（新增）：粘贴 300～1200 字稿件并给出 2～5 个机构全称与
   数量相同的简称（每个名称都须在稿中出现），系统只用本稿中名称周围的语境拟合
   字符 2～3 元 TF-IDF，结合字形相似度求出简称到全称的一对一最高分对应；
   替代对应接近或语境不足时标记**待核对**，不强行确认。

## 技术栈

- **FastAPI**：HTTP 接口与演示页面
- **scikit-learn**：字符 2~3 元 TF-IDF（`TfidfVectorizer(analyzer="char", ngram_range=(2,3))`）
  与余弦相似度（推荐语料与核查语境各自独立拟合）
- **SQLite**（WAL 模式）：推荐会话状态、异步重算任务、排除集、揭示票据的持久化
- 原生 HTML/CSS/JS 前端，无构建步骤（`app.js` 推荐视图、`abbr.js` 核查视图）


## 数据

`app/articles_data.py` 内置 30 篇中文文章，每篇含 `id / 标题 / 正文 / 单一主题 / 作者`：

- 6 个主题（人工智能、医疗健康、金融投资、旅游地理、美食烹饪、体育竞技），每主题 5 篇；
- 10 位作者，每人 3 篇且分布在 3 个不同主题；同一主题内 5 位作者互不相同。
  因此标准“每主题一篇”的队列天然满足作者不重复，而约束校验对任意配额仍然生效。

## 推荐算法

### 相关度

1. TF-IDF **只在 30 篇文章正文上 `fit`**，兴趣短文只做 `transform`，特征空间与
   IDF 权重完全由文章决定；
2. 特征为字符二元、三元组（已断言词表中不存在单字特征）；
3. 兴趣向量与每篇文章向量计算余弦相似度，截断到 `[0,1]` 作为相关度。

### 全局最优队列

求解器 `app/optimizer.py` 用逐主题组合枚举 + 分支定界求**精确全局最优**（非近似）：

- 六个主题按配额 `q_t` 枚举候选组合，强制作者互不重复；
- 给定入选文章集合，由重排不等式，按相关度降序放入权重降序的位置即最优排列；
- 目标函数：`Σ_{pos=1..6} (7 - pos) × 相关度`，位置权重为 6,5,4,3,2,1；
- 存在已揭示前缀时，前缀的位置与文章固定，只对剩余位置重新求全局最优；
- 分支定界的上界忽略跨主题作者冲突（只会高估），保证不剪掉真正的最优解；
- 单元测试中与全暴力枚举对拍，多次随机相关度/配额下结果完全一致；
- 平局按 `article_id` 确定性打破，重复求解结果稳定。

## 揭示规则与并发语义

- 每次点击揭示**两篇**，已揭示文章及其顺序**永久固定**并占用主题配额；
- 可随时修改兴趣、配额或排除/取消排除未揭示文章：未揭示位置按新条件重新全局优化，
  已揭示前缀保持不变；
- 无可行解时保留已揭示内容并停止揭示，接口返回明确原因（如某主题候选不足）；
- **同一条件（世代 generation）和同一进度点的“下一组”只推进一次**：
  进程内写锁串行化所有请求，并以 2 秒宽限窗口（可用环境变量 `REVEAL_CLAIM_TTL` 调整）
  识别并发批次，窗口内重复/并发请求复用首个请求的结果（`idempotent=true`）而不重复推进；
  窗口过后人工的下一次点击正常开启新一轮揭示；
- **慢重算可并发改条件，迟到结果不得揭示旧推荐**：每次条件变更生成新世代并把旧任务
  标记为 `stale`，后台 worker 写回前再次核对世代号，过期结果一律拒绝落库；
- 重算失败只把任务标记 `failed`，**不推进进度**，揭示接口会拒绝并提示；
- 所有状态落盘，**进程重启后已揭示前缀、世代、条件完整恢复**。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/status` | 当前状态、最新任务、完整推荐计划、文章清单 |
| `GET` | `/api/articles/{id}` | 单篇文章正文 |
| `PUT` | `/api/condition` | 修改兴趣和/或配额（请求体含 `interest`、`quotas`、可选 `compute_delay_ms`） |
| `POST` | `/api/exclusions` | 排除一篇未揭示文章（`article_id`） |
| `DELETE` | `/api/exclusions/{id}?compute_delay_ms=` | 取消排除 |
| `POST` | `/api/reveal` | 揭示下一组两篇 |
| `POST` | `/api/reset` | 重置演示数据 |

`compute_delay_ms` 用于在演示中人为制造慢重算（0~30000 毫秒），观察并发改条件与
过期保护行为。交互式文档见 `/docs`。

## 机构简称核查

### 输入约束

- 稿件 300～1200 字；机构全称 2～5 个，简称数量必须与全称相同；
- 每个名称（含简称）都必须在稿件中实际出现，否则接口返回 422 并列出缺失名称；
- 全称之间、简称之间不得重复，简称不得与全称同名。

### 核查算法（`app/abbr_checker.py`）

1. **只拟合本稿语境**：对每个名称取全部出现位置两侧各 24 字的窗口，窗口内出现的
   任何已知名称统一替换为占位符（避免名称自身字形把语境相似度“灌高”），合并为该
   名称的语境内文档；`TfidfVectorizer(analyzer="char", ngram_range=(2,3))` 仅在
   这些文档上 `fit`，不引用任何外部语料（测试断言词表中不存在单字特征）。
2. **双证据打分**：简称文档与全称文档的 TF-IDF 余弦相似度（权重 0.6）+ 字形相似度
   （权重 0.4；字形 = 0.7×`SequenceMatcher` 比率 + 0.3×简称字符在全称中的子序列覆盖率，
   可捕捉“北京大学→北大”这类抽字关系）。
3. **一对一最优**：n≤5 时全排列枚举（至多 120 种）求总得分最高的一对一匹配，
   平局按排列字典序确定性打破，不做贪心近似。
4. **不强行确认**，出现任一情形即把该对标记为 `review`（待核对）并逐条写明依据：
   - 与次优全称的得分差小于 0.08（替代对应接近，存在指错风险）；
   - 简称或全称的单侧有效语境少于 20 字（语境不足）；
   - 语境余弦相似度低于 0.15，或综合得分低于 0.45。
5. **嵌在全称内的简称不重复计数**：简称出现区间被任一全称区间完全包含时标注
   `embedded_in`，不计入独立出现次数，但仍在原文位置中高亮（紫色虚下划线）。

网页对每处原文位置按全称/独立简称/嵌套简称三色标注，并展示每个名称实际参与拟合的
语境文档、全部阈值与每对的综合得分、语境分、字形分、次优对应与得分差，判断过程可核对。

### 并发与过期语义（`app/abbr_jobs.py`）

- 核查为异步任务：提交即返回 `request_id`，前端轮询 `/api/abbr/jobs/{id}`；
- 每次提交生成新的服务端世代并把未完成的旧任务立即标记 `stale`，worker 写回前
  再次核对世代，**迟到结果一律丢弃，不会覆盖新输入对应的判断**；
- 前端另维护本地世代 `client_token`（提交时上送、服务端原样回显）：稿件或名称
  输入框一有变更就立即撤下页面上的旧判断并作废轮询，响应 token 不匹配则不渲染，
  形成前后端双重过期保护；
- `compute_delay_ms` 可人为制造慢核查，用于演示该保护；
- 核查结果随稿件即算即弃，不需要跨重启保留，因此任务注册表为进程内结构，
  与推荐系统的持久化世代互不干扰。

## 目录结构

```
app/
  articles_data.py   # 30 篇本地文章语料
  tfidf_model.py     # 仅文章拟合的字符 2~3 元 TF-IDF 单例（推荐功能）
  optimizer.py       # 精确全局最优求解器（枚举 + 分支定界）
  database.py        # SQLite 持久化、世代、票据、串行写事务
  worker.py          # 后台异步重算线程与过期/失败处理
  abbr_checker.py    # 简称核查：语境 TF-IDF + 字形相似度 + 一对一匹配（纯函数）
  abbr_jobs.py       # 核查异步任务注册表、世代与迟到结果丢弃
  main.py            # FastAPI 路由与生命周期
  static/            # 演示网页（index.html / app.js / abbr.js / style.css）
tests/               # 求解器对拍、TF-IDF 约束、端到端 API、核查算法与前端测试
Dockerfile, docker-compose.yml, requirements.txt
```

## 已知边界与取舍

- 数据规模固定为 30 篇/6 位置，精确枚举最坏情况单次求解约 0.2 毫秒；
  若文章量大幅增长，需要替换为整数规划或带剪枝的搜索，接口层无需改动。
- 演示采用单会话全局状态（对应两个浏览器窗口共享同一进度的设定）；
  多用户隔离需要再引入会话 ID 维度。
- 并发去重的宽限窗口是时间启发式（默认 2 秒）：足以覆盖线程调度、双击与网络重试，
  又远小于人工两次点击间隔；可通过环境变量调整。
